Локальное Windows-приложение для голосового ввода в активные программы и отдельной расшифровки аудио/видео файлов.

## Запуск

1. Установите Python 3.10 или 3.11 x64 и включите **Add python.exe to PATH**.
2. Запустите `install.bat`.
3. Запустите `run.bat`.
4. Для сборки отдельного приложения используйте `build_exe.bat`.

## Основные возможности

- Локальная финальная расшифровка через Whisper/faster-whisper.
- Финальная локальная расшифровка через Parakeet ONNX.
- Отдельная вкладка **Файлы** для расшифровки аудио/видео: `wav`, `mp3`, `m4a`, `mp4`, `webm`, `ogg`, `flac` и другие форматы с аудиодорожкой.
- Во время расшифровки файла показывается процент обработки, а обработанные блоки сразу появляются в результате. Таймкоды отображаются только если включена опция **Точные таймкоды**.
- Для файлов доступны выключенные по умолчанию опции **Точные таймкоды** и **Определять говорящих**. При первом использовании нужно загрузить дополнительные локальные модели во вкладке **Модели**.
- Дополнительные модели: VAD для точных таймкодов и Sortformer Diarization v2.1 для диаризации до 4 спикеров. В v4.1.3 speaker labels добавляются в сегменты сразу по мере вывода, чтобы пользователь видел говорящих вместе с уже расшифрованными частями файла.
- Расшифровка файлов не вставляет текст автоматически и не копирует его в буфер: пользователь сам нажимает **Скопировать результат**.
- Диктовка и расшифровка файла не запускаются одновременно, чтобы не конфликтовать за модель/ресурсы.
- Загрузка, удаление и выбор моделей. При скачивании в таблице показываются кружок-индикатор и процент прогресса.
- Distil Whisper убран из основного списка: он не подходит для русскоязычной транскрибации. В списке оставлены только мультиязычные Whisper-модели OpenAI-origin в формате CTranslate2 для faster-whisper.
- В настройках можно указать Hugging Face token для авторизованной загрузки моделей. Токен не зашит в приложение и хранится только локально после ввода пользователем.
- Активной можно выбрать только доступную/загруженную модель.
- `Whisper — Small` доступна по умолчанию и отображается в таблице как **Готова по умолчанию**.
- Глобальная горячая клавиша для старта/остановки записи. Если выбранная комбинация не поддерживается клавиатурной библиотекой, поле подсвечивается, а предыдущая рабочая комбинация остаётся активной.
- Режим горячей клавиши (Настройки → «Режим клавиши»): **Переключатель** (нажать — запись, нажать снова — расшифровка) или **Push-to-Talk** (держать — запись, отпустить — расшифровка). Смена режима применяется без перезапуска. Для Push-to-Talk рекомендуется комбинация с Ctrl или Alt.
- Во время финальной расшифровки диктовки локальной моделью плашка overlay и статус показывают прогресс «Распознаю: X%»; если расшифровка укладывается в 2 секунды — результат появляется сразу, без процента.
- `Esc` во время записи или распознавания отменяет текущую операцию: история и буфер обмена не меняются.
- Постоянная маленькая плавающая плашка поверх окон: `Ready`, `Запись`, `Распознаю`, `Отменено`, `Ошибка`. Плашку можно перетаскивать; её положение сохраняется и восстанавливается после перезапуска.
- Если поле ввода не найдено, финальный текст появляется под плашкой, копируется в буфер и сохраняется в истории.
- В окне результата под плашкой можно нажать **Скопировать** или `Esc`, чтобы вернуться в `Ready`. В этом случае `Esc` не удаляет транскрипт.
- При закрытии крестиком приложение скрывается из основной панели задач и продолжает работать в системном трее.
- Закрыть приложение полностью можно через иконку в трее: **Выйти**.
- Автозагрузка вместе с Windows.
- Автосохранение настроек.
- Выбор микрофона в настройках с приоритетом Windows WASAPI shared и fallback на другие устройства.
- Режим совместимости с онлайн-созвонами: меньше конфликтов с Zoom/Teams/Meet/браузером, понятная ошибка, если микрофон всё равно занят.
- Кнопка **Автонастройка микрофона** для диагностики доступа.
- При первом запуске приложение автоматически пробует найти рабочий доступный микрофон и сохраняет найденное устройство.
- Защита от двойной вставки во вкладке **Диктовка**: если курсор стоит внутри самого Voice Input Local, системный Ctrl+V не отправляется.
- Единая иконка приложения в окне, трее и EXE-сборке.
- История расшифровок с датой в формате `дд.мм.гггг чч:мм`.
- Логи для диагностики.

## Расшифровка файлов

Во вкладке **Файлы** можно выбрать аудио или видеофайл и запустить локальную расшифровку выбранной моделью. Этот сценарий отделён от диктовки:

- файл не вставляется автоматически в активное поле;
- файл не копируется в буфер автоматически;
- результат показывается в приложении;
- распознанные блоки появляются сразу по мере обработки;
- для Whisper короткие 1–3 секундные сегменты объединяются в более естественные реплики;
- Parakeet-разбивка сохраняется без агрессивной склейки;
- если включена диаризация, текст сначала показывается сразу, а speaker labels применяются после post-processing;
- таймкоды у блоков показываются только при включённой опции **Точные таймкоды**;
- прогресс показывается как процент и как обработанное время от общей длительности;
- результат сохраняется в историю с пометкой **Файл** и именем исходного файла;
- пользователь сам нажимает **Скопировать результат**, когда текст нужен в буфере.

Во время обработки файла горячая клавиша диктовки временно игнорируется, а плашка показывает компактный процент обработки файла.

## Точные таймкоды и диаризация

Вкладка **Файлы** содержит две дополнительные функции, доступные из коробки, но выключенные по умолчанию:

- **Точные таймкоды** — использует дополнительную VAD-модель и более детальную разбивку сегментов. Режим медленнее, но удобнее для интервью, созвонов и субтитров.
- **Определять говорящих** — требует дополнительную Sortformer ONNX-модель. В результате блоки отображаются как `Спикер 1`, `Спикер 2` и т.д. На первом этапе используется segment-level назначение говорящего.

Если нужная дополнительная модель не загружена, приложение попросит загрузить её во вкладке **Модели**. Эти функции применяются только к обработке файлов и не влияют на диктовку.

Структурированные блоки файла сохраняются в истории вместе с обычным текстом: начало, конец, говорящий и текст.

## Почему live-расшифровка убрана

Live-настройки убраны из интерфейса стабильной ветки. Предыдущая near-live реализация запускала распознавание коротких WAV-фрагментов, что на обычном CPU давало задержку, пустые промежуточные результаты и нестабильное определение языка на коротких репликах.

Основной сценарий: пользователь нажимает hotkey (или удерживает его в режиме Push-to-Talk), диктует, останавливает запись, приложение делает финальную локальную расшифровку (с индикатором прогресса «Распознаю: X%» в overlay) и вставляет/сохраняет результат.

Чтобы вернуть live-режим на хорошем уровне, нужен отдельный streaming-pipeline: audio ring buffer, stable-prefix commit, buffer trimming, фиксированный язык для live, отдельные partial/final states и, желательно, более быстрый backend или GPU.


## Микрофон, созвоны и настройки Windows

В Windows desktop-приложения могут не отображаться в верхнем списке отдельных приложений. Проверьте общий переключатель:

```text
Параметры → Конфиденциальность и безопасность → Микрофон → Разрешить классическим приложениям доступ к микрофону
```

Во вкладке **Настройки** есть кнопка **Автонастройка микрофона**, которая автоматически находит работающий микрофон.

Если вы запускаете программу через `run.bat`, Windows может показать в списке обращений `python.exe`, потому что приложение работает через локальный Python. После сборки `build_exe.bat` и запуска `dist\VoiceInputLocal\VoiceInputLocal.exe` Windows обычно показывает уже `VoiceInputLocal.exe`, если desktop-app detection сработал.


### Онлайн-созвоны

В настройках включён по умолчанию режим **Совместимость с онлайн-созвонами**. Он открывает микрофон через Windows WASAPI shared, где это возможно, и пробует fallback на другие input-устройства, включая WDM-KS как поздний вариант для отдельных USB/Bluetooth-гарнитур. Это снижает конфликты с Zoom, Microsoft Teams, Google Meet и браузерами.

Абсолютной гарантии нет: если другое приложение или драйвер держит микрофон в эксклюзивном режиме, Windows может не разрешить вторую запись. В таком случае приложение покажет понятное уведомление, не упадёт и запишет подробные попытки открытия микрофона в `app.log`.

## Тёмная тема и QScrollArea (заметка для разработчиков)

Приложение использует тёмную тему, заданную через глобальный `APP_STYLE` в `voice_input_app/ui.py`.

Ключевое правило, от которого зависит тёмный фон всего интерфейса:

```css
QWidget { font-size: 13px; color: #f4f4f5; background: #101114; }
```

**Если убрать `background: #101114` из этого правила, фон настроек (и других вкладок с QScrollArea) станет белым на Windows.**

Причина: PySide6/Qt на Windows присваивает каждому `QScrollArea.viewport()` собственную `QPalette` с системным цветом окна (белым). Stylesheet, применённый к `QScrollArea`, **не наследуется** viewport'ом. Единственный надёжный способ — задать `background` на глобальном уровне через селектор `QWidget`.

Подходы, которые **не работают**:

- `tab.setStyleSheet("background: transparent;")` — каскадируется на все дочерние виджеты (`QLineEdit`, `QComboBox`, `QPushButton`), обнуляя их тёмный фон `#18181b`.
- `scroll.setStyleSheet("QScrollArea > QWidget { background: transparent; }")` — Qt CSS не поддерживает дочерний комбинатор `>`.
- `scroll.viewport().setAutoFillBackground(False)` — ненадёжно, viewport пересоздаётся при `setWidget()` и сбрасывает палитру.
- `QWidget#SomeId { background: transparent; }` — не помогает, потому что viewport `QScrollArea` не является этим виджетом.

Подробный комментарий с этой же информацией есть в методе `_settings_tab()` в `ui.py`.

## Важные ограничения

### Вставка в программы

Windows не даёт гарантировать вставку в абсолютно любое приложение. Приложение старается вставлять текст только туда, где есть активное поле ввода/курсор. Вставка может быть заблокирована в UAC-окнах, защищённых полях, играх, удалённых рабочих столах, приложениях с правами администратора или нестандартных интерфейсах.

### Parakeet

Parakeet в этой сборке используется как финальный локальный движок. Live-режим для Parakeet отключён. Для длинных записей Parakeet использует чанки с overlap и дедупликацией, чтобы снизить ошибки на стыках.

## Где лежат данные

Приложение хранит данные в:

```text
%LOCALAPPDATA%\VoiceInputLocal\
```

Внутри:

```text
config.json          настройки
history.sqlite3      история
models\              локальные модели
recordings\          временные аудио, если включена отладка
logs\                логи приложения
```

## Логи

Откройте вкладку **Настройки** и нажмите **Открыть папку логов**.

Основные файлы:

```text
app.log
errors.log
transcription.log
```

Если Parakeet или Whisper падают, пришлите содержимое `errors.log` и последние строки `transcription.log`.

## Облачные STT-модели (v4.3.0)

Помимо локальных Whisper и Parakeet, приложение умеет ходить в облачные
сервисы распознавания речи — это повышает качество, особенно на сложных
записях, но требует интернета и передаёт аудио на серверы провайдера.

Поддерживаются два направления:

- **OpenAI-совместимый API** — официальный OpenAI Whisper API
  (`https://api.openai.com/v1`), Groq (`https://api.groq.com/openai/v1`)
  или любой совместимый прокси, у которого есть endpoint
  `/v1/audio/transcriptions` и `/v1/models`.
- **ElevenLabs Speech-to-Text** — отдельный endpoint
  `https://api.elevenlabs.io/v1/speech-to-text`, модели Scribe.

### Как настроить

1. Открой **Настройки → Облачные модели**.
2. Введи **OpenAI API Key** и, если нужно, измени **Base URL**
   (для Groq укажи `https://api.groq.com/openai/v1`).
3. Нажми **«Проверить соединение и обновить список моделей»** — combo
   «OpenAI Model» заполнится моделями, которые провайдер реально отдаёт
   (фильтрация по STT-ключевым словам: `whisper`, `transcribe`, `scribe`,
   `stt`, `speech-to-text`, `asr` и др.). Аналогично для ElevenLabs.
4. На вкладке **Диктовка** в списке моделей появится группа «── Облачные ──».
   Выбери нужную и начинай диктовать.

### Что происходит при потере связи

- Перед каждым запросом приложение делает **проактивную проверку
  интернета** (TCP-connect к хосту провайдера).
- Если интернета нет / ключ невалиден / провайдер ответил 5xx или 413 —
  программа автоматически **переключается на локальную модель**,
  заданную в поле **«Fallback при сбое облака»** (по умолчанию Whisper Small).
- В статус-баре и в системном трее появится уведомление с причиной.
- Чтобы вернуться к облачной модели после восстановления связи — просто
  выбери её в списке на вкладке «Диктовка» повторно.

### Длинные надиктовки

Если запись длиннее, чем **«Длина чанка для облака»** (по умолчанию 60 секунд),
приложение автоматически нарезает WAV на чанки с overlap 0.3 секунды и
отправляет их параллельно (до 3 потоков). Результаты склеиваются в исходном
порядке. Это нужно потому, что у OpenAI/Groq есть лимит размера запроса
(25 МБ у официального API).

### Где смотреть проблемы

В `app.log` пишутся подробные строки про каждый cloud-запрос: URL, HTTP-статус,
длительность, какие модели нашёл `/v1/models` и какие из них прошли STT-фильтр.
При проблемах с подключением (таймаут, корпоративный прокси) логируются
переменные окружения `HTTPS_PROXY`/`NO_PROXY`. С v4.5.1 для OpenAI-совместимых
запросов диктовки логируется также Initial Prompt: `openai prompt: will_send=...
chars=... preview=...`.

### Initial Prompt для OpenAI-совместимого STT (v4.5.1)

Поле **«OpenAI Initial Prompt»** в настройках облачных моделей задаёт пример
стиля пунктуации и форматирования, который передаётся Whisper вместе с
аудиофайлом (параметр `prompt` в multipart/form-data). Это **не команда**
для модели и **не меняет содержание** расшифровки — только стабилизирует
оформление: расстановку запятых, тире, кавычек «ёлочек» для прямой речи,
точек с запятой, заглавных букв в начале предложений.

Дефолтное значение — короткий русский пример с разными типами знаков. Можно
переписать под свой стиль (кейс: технический жаргон, форматирование списков,
иностранные слова), очистить (тогда prompt не отправляется в API) или
вернуть кнопкой **«Сбросить к дефолту»**.

Ограничения:

- Применяется только к **диктовке**, не к расшифровке файлов через облако
  (для длинных файлов с разнородным содержимым prompt бесполезен).
- Только для **OpenAI-совместимых** провайдеров. В секции ElevenLabs
  поле не отображается — там endpoint не поддерживает prompt.
- Лимит OpenAI — 224 токена. Если ввести больше, API обрежет с конца
  автоматически, ошибки не будет. Рекомендуемый объём — около 50 слов.
- Не отправляется для модели `gpt-4o-transcribe-diarize` (она единственная
  из OpenAI-моделей не поддерживает prompt — иначе вернёт 400).
- Prompt должен совпадать с языком аудио. Дефолт на русском подходит для
  русской диктовки. Для других языков перепиши пример.

### Постобработка расшифровки облачной LLM (v4.6.0)

Если включить **«Улучшение расшифровки»** в настройках, то при диктовке через
облачную STT-модель сырой текст распознавания автоматически прогоняется через
вторую облачную LLM (OpenAI-совместимый `chat/completions`), которая исправляет
пунктуацию, грамматику, англицизмы и термины, переводит числа из слов в цифры,
оформляет цитаты, диалоги и списки. Готовый текст вставляется или показывается
в overlay так же, как обычный результат; пока идёт обработка, плашка показывает
«Улучшаю текст…».

Постобработка настраивается отдельно от STT: свой **API URL**, **API Key**,
список моделей (кнопка «Проверить соединение»; в списке остаются только
модели, умеющие работать с текстом на входе и выходе — STT/Whisper, TTS,
embeddings и т.п. отфильтрованы), редактируемый **системный
промпт** с кнопкой «Сбросить к дефолту». Переключатель **«Рассуждение
(Reasoning)»** по умолчанию выключен (цель полного цикла «надиктовал → получил
текст» — не более ~10 секунд); при включении доступен выбор уровня
**low / medium / high** (выше — качественнее, но медленнее).

Ограничения и поведение:

- Работает **только** при диктовке через облачный STT. При локальной модели и
  при расшифровке файлов постобработка не выполняется.
- При запуске программы, если постобработка включена, соединение с LLM
  проверяется автоматически (как со STT-моделями); при недоступности
  показывается уведомление.
- Если облако STT недоступно и сработал fallback на локальную модель —
  постобработка не запускается (текст уже локальный).
- При ошибке LLM показывается сырой текст расшифровки и статус
  «Постобработка недоступна. Показан исходный текст расшифровки».
- Защита от prompt-injection: сырой текст оборачивается маркерами
  `⟦РАСШИФРОВКА⟧ … ⟦/РАСШИФРОВКА⟧`, модели запрещено выполнять его как
  команды — даже если в речи прозвучало «составь список» или «напиши письмо»,
  фраза будет лишь грамотно оформлена, а не выполнена.

### Облачная суммаризация (v4.8.0)

Суммаризацию расшифровки можно выполнять не только локально, но и через
облачную LLM (OpenAI-совместимый `chat/completions`) — это быстрее и не
нагружает компьютер. Способ выбирается в **Настройки → Суммаризация**
переключателем **«Способ суммаризации»: Локально / Облако** (по умолчанию —
локально). При выборе «Облако» открывается блок подключения: **API URL**,
**API Key**, список моделей (кнопка «Проверить соединение»). На вкладке
«Файлы» по-прежнему только чекбокс «Суммаризация» — все настройки способа
вынесены в «Настройки».

Системный **промпт суммаризации общий** для локального и облачного режима:
состоит из роли, задачи, ограничений и формата ответа, при первом открытии
уже заполнен значением по умолчанию (кнопка «По умолчанию» возвращает его).
Как и в постобработке, расшифровка оборачивается маркерами
`⟦РАСШИФРОВКА⟧ … ⟦/РАСШИФРОВКА⟧`, поэтому модель не выполняет команды,
случайно прозвучавшие в записи, а только резюмирует их как часть разговора.

Переключатель **«Рассуждение модели (Reasoning)»** применяется к обоим
режимам: для облачных моделей передаётся уровень рассуждения
(**low / medium / high**), для локальной Qwen3 включается режим thinking.

Поведение и ограничения:

- Если способ — облако, при запуске программы соединение и список моделей
  проверяются автоматически (как со STT и постобработкой).
- При недоступности облака (нет сети, сбой сервиса, лимит) перед стартом и
  во время суммаризации показывается диалог с выбором: **выполнить локальной
  моделью** или **отменить**. Если локальная модель не скачана — выводится
  подсказка скачать её на вкладке «Модели».
- **Лимиты провайдера (например, Groq):** при ошибке **429** (лимит запросов
  в минуту/токенов в минуту) запрос автоматически повторяется с паузой. При
  уровне рассуждения **«высокий»** модель может исчерпать лимит токенов на
  размышление и не вернуть ответ — в этом случае показывается подсказка
  снизить уровень Reasoning или отключить его (или выполнить локально).

Расшифровка файла теперь сохраняется в **истории с разметкой** тайм-кодов и
спикеров (если они были включены при расшифровке), поэтому суммаризация из
истории сохраняет разделение по спикерам и даёт более качественный результат.

## Настройки

Настройки сохраняются автоматически.

- **Автоматически вставлять текст** — после финальной расшифровки приложение пробует вставить текст в активное поле.
- **Безопасная вставка** — если включена, приложение вставляет только когда Windows видит активное поле ввода. Если выключена, приложение пробует отправить `Ctrl+V` в активное окно, но только если поле ввода было обнаружено при старте записи.
- **Плавающая плашка** — постоянный компактный индикатор поверх окон.
- **Автозагрузка** — запуск Voice Input Local вместе с Windows.
- **Микрофон** — выбор конкретного устройства ввода или системного микрофона по умолчанию.
